# CC-006 — Local bounded Outlook sync orchestration

Implemented locally, 2026-11-10. This is preparation for M3D, not live M3D
acceptance or permission to authenticate/read a mailbox.

`lib/email/bounded-sync.mjs` exports `runBoundedMailboxSync`. Callers provide an
explicit data root, opaque account/run IDs, expected mailbox revision, previous
health snapshot, a window of at most 31 days, and trusted inspection/persistence
callbacks. Production callers must resolve the root through `path-resolver.mjs`,
validate the authenticated account and obtain the required live authorization.
There is no default Graph client, CLI command, scheduler, OAuth or cursor access.

The coordinator records syncing through the existing mailbox owner writer before
inspection, persists observations before publishing complete coverage, and uses
revision barriers for every health publication. It reports only fixed categories
on inspection/persistence failures. It does not schedule retries or advance a
checkpoint on partial/failing observation persistence. The connection observation
is preserved rather than inferred. Folder scope is `all_messages` because the
existing client reads `/me/messages`; this does not claim coverage of every
special folder. A bounded window is not whole-mailbox synchronization.

A supplied previous syncing state requires reconciliation. Exact known start
replay also stops before inspection. Stale revisions and altered operation payloads
are rejected by the owner store. Backoff is respected; once elapsed, an explicit
run clears scheduled-retry metadata while retaining the attempt count until
success. A checkpoint-publication failure propagates without automatic replay.
Callbacks must not submit applications, use verification codes or send mail.

`inspectMailbox` now accepts an optional explicit `until`; the existing default
is preserved. This lets the coordinator's requested coverage match the actual
inspection window. Existing observation persistence remains review-only.

Validation:

```sh
node --test --test-reporter=dot tests/outlook-bounded-sync.test.mjs tests/outlook-readiness.test.mjs tests/career-central-platform-recovery.test.mjs tests/career-central-persistence.test.mjs tests/outlook-email.test.mjs
```

90 passed, 0 failed. Ten new coordinator tests cover publication ordering, partial
coverage, rate limiting, persistence uncertainty, replay/stale revisions,
malformed results, final-publication conflict, backoff and actual analyzer/writer
integration with fictional mail. No web change; no web build/browser test needed.
No dependency, live account, actual mailbox, credential, private source record,
application submission or deployment was used.

Remaining: native vault validation, authenticated account binding at a future
entry point, explicit interrupted-run reconciliation UI/command, live read-only
acceptance and protected continuation integration. Observation commit and health
commit are deliberately separate; crashes may leave syncing metadata requiring
review. Completion depends on the trusted inspector honoring the requested window
and reporting pagination honestly. No exactly-once guarantee or automatic restart
is claimed. Legacy account/folder rebinding remains unsupported.
