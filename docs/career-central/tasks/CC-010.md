# CC-010 — Safe post-callback Gmail OAuth diagnostics

Implemented locally, 2026-11-10. User reported generic GMAIL_SIGN_IN_FAILED after
Google consent and explicitly prohibited mailbox access during diagnosis.
Initial HEAD `6b19550b`, clean tree. No private OAuth client/config, authorization
code, token, account profile or message was accessed. No live sign-in attempted.

## Evidence and bounded diagnosis

User confirmed the previous local page said "Sign-in received. Return to the
terminal." That string was sent only after the WSL listener validated state and
received one nonempty authorization code. Thus the historical callback reached
WSL; failure happened afterward. The prior ephemeral port is no longer listening.
The old code discarded all unrecognized exchange/token-info/profile errors, so
its exact historical downstream cause cannot be reconstructed from that error.
No guessed API/credential/network cause is presented as a verified fact.

A separate synthetic Windows-to-WSL HTTP probe passed from native PowerShell to
an IPv4-only WSL listener. It imports no OAuth/config/credential module and changes
no network settings. The installed SDK also reached Google's public discovery
endpoint (HTTP 200) and public token-host root (expected HTTP 404); those requests
used no identity, credential or token and were not mailbox requests. These checks
establish current local forwarding and basic HTTPS reachability, not live OAuth
or Gmail account acceptance.

## Fixes

- `oauth-diagnostics.mjs`: closed stage/category dictionaries reconstruct fixed
  error messages, optional numeric HTTP status and allow-listed network codes.
  Known Google OAuth error identifiers distinguish invalid client/grant/redirect,
  token rejection, denial and temporary errors. Nested DNS/TLS/timeout errors are
  classified without exposing raw messages, stack, config, headers, URLs or data.
  CLI diagnostics revalidate/project fields; external text is never forwarded.
- `gmail-auth.mjs`: stage-aware callback/exchange/token-info/account verification
  events, sanitized failure summaries and optional diagnostics sink. SDK client
  transport enforces both retry=false and nested retryConfig.retry=0/no retries;
  the SDK's own auth defaults otherwise override plain transporter defaults.
  Verified TLS, timeout and redirect refusal remain. Returned scope/audience/
  account validation, session-only credentials and consent gate are unchanged.
- `oauth-loopback.mjs`: ready/accepted/rejected/closed events without request data;
  browser page explicitly says authentication is still being verified. Listener
  stays IPv4-loopback-only and active through exchange/verification. Close is
  awaited on completion/failure/timeout. State/PKCE/single-code guards remain.
- `gmail-client.mjs`: only closed API-disabled signals (accessNotConfigured or
  SERVICE_DISABLED) may be extracted from provider error JSON. No raw provider
  messages/details escape. This distinguishes disabled Gmail API at the profile
  step from OAuth code exchange without adding permission or accessing messages.
- `gmail-email.mjs`: optional --diagnostics prints sanitized events to stderr;
  failure summaries retain safe stage/category even without it. The flag alone
  cannot authorize sign-in or open private config.
- `gmail-loopback-check.mjs`: reusable synthetic connectivity probe, no OAuth or
  mailbox operations. No Windows/WSL/firewall forwarding settings were changed.
