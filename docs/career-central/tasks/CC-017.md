## C0 — local readiness (no AWS, no network)

1. **Store port.** `updateSource(root, sourceId, fn)` and `readSource` scoped to one partition, plus scheduler and authorization records. Adapters: file (current), in-memory (tests), later S3+DynamoDB. One contract-test suite runs against every adapter: compare-and-swap conflict, crash between partition write and release, lease fencing, idempotent alert projection, unknown `schemaVersion` fails closed.
2. **Unchanged-snapshot fast path.** When a complete snapshot changes no posting content, availability or missing count, update only the source control record (snapshot-level `lastObservedAt`, checkpoint, nextDueAt) and skip the partition rewrite. Test: 100 unchanged polls produce 0 partition writes and an identical shortlist view.
3. **Eligibility projection.** Export a versioned, minimized projection (verified graduation month, authorization/citizenship/sponsorship booleans, verified skills, earliest start month, role weights, threshold, hashed application-history and blacklist keys). The evaluator accepts it in place of the full profile and ledger. Tests: identical match results versus the full context on the real-shape fixture corpus; an allowlist test fails if any other field (résumé, contacts, email, compensation, free text) appears.
4. **Telemetry.** EMF metric and JSON log formatter with correlation IDs. Redaction tests: no description text, URL query strings, profile values or answers in output.
5. **Handler wrapper.** `handler(event)` → `runMonitorTick` with injected adapters, clock and fetch reader. The deadline budget stops before the Lambda timeout; reserved-concurrency assumptions are documented.
6. **Dev-only fixture provider** (rejected in prod config), so cloud acceptance can produce controlled new, changed and expired postings without touching real employer feeds.
7. Apply the approved local `migrate-store --apply`.

C0 acceptance: all existing monitor, scheduler and browser suites plus the new contract and projection tests pass; the simulated 8-hour scenario passes against the in-memory adapter; no change to application, email or résumé data.

### C1 preparation without provisioning (2026-11-11)

Done:
- `cloud-monitor-store.mjs` implements the store port over two minimal client interfaces: S3-like objects with ETags and `ifMatch`/`ifNoneMatch`, and a DynamoDB-like table with version-conditional puts.
- In-memory fakes run it through the full contract suite: 7 shared scenarios, plus replay after a crash between the S3 write and the DynamoDB update, and zero partition PUTs across 50 unchanged polls.
- The adapter keeps a snapshot for the port's synchronous `readAll()`. The handler calls `refresh()` at the start of **every** invocation, warm or cold. Every write re-reads current state and is conditional (S3 `If-Match` / DynamoDB version), so a stale instance can't overwrite newer employer state.
- Cross-invocation scheduling uses a **distributed, expiring tick lease** item plus the per-source leases in control items; no in-process lock is relied on. Reserved concurrency 1 remains an extra guard, not the mechanism.

Next steps that still need no AWS account or resources:
1. Thin SDK-backed client wrappers matching the two interfaces. This adds `@aws-sdk/client-s3` and `@aws-sdk/client-dynamodb` only after dependency approval (§15 item 4), and is tested with recorded request shapes, not live calls.
2. A `cloud-push` / `cloud-pull` export format: partition + control + projection bundle with canonical-hash round-trip verification and owner-flag handover, tested between file and cloud-shaped stores.
3. A Lambda bundle entry (`handler` export wired from environment configuration) and a size/cold-start check with Node 22 locally.
4. IAM policy documents as JSON with least-privilege assertion tests, ready for CDK once `infra/` is approved.
5. Alarm and budget definitions as data, derived from the telemetry metric names.

## C1 — AWS dev, then prod (after explicit approval)

CDK stack per environment:
- DynamoDB (on-demand, PITR).
- S3 (Block Public Access, SSE-S3, versioning, non-current expiry 30 days, TLS-only policy).
- `monitor-tick` Lambda (Node 22, arm64, 512 MB, timeout ≤ 300 s, reserved concurrency 1, no VPC, least-privilege role).
- EventBridge Scheduler `rate(5 minutes)`.
- Log group with 14-day retention; ≤ 10 aggregate metrics and ≤ 10 alarms; an AWS Budget.
- GitHub OIDC roles.

Local `cloud-push --source`, `cloud-pull --source` and `monitor pull`.

Acceptance (dev):
- `cdk synth`, cdk-nag and assertion tests pin IAM actions/resources, encryption, retention and the absence of a VPC/NAT.
- Fixture source: baseline quiet; one controlled change → exactly one alert; replay or second invocation → no duplicate.
- An injected timeout mid-poll → `worker_lost`, then reclaim; a stale writer gets a 412 and nothing is corrupted.
- Retry-After and backoff honored; authorization expiry stops polls; `disable schedule` stops all activity.
- Restore drill: one partition from an S3 version plus the control item from PITR.
- Logs contain no forbidden fields (sampled check); measured cost for one week is within the budget forecast.

Then, separately approved: 1–3 real sources with owner=cloud (local revoked) and one week of observation (health, lag, no duplicates) before promotion to prod.

Out of scope: SQS, hosted dashboard, Cognito/API, browser workers, AI inference, email, notifications, applications.
