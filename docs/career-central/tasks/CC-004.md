## Result and decisions

Existing stores/owner locks remain authoritative: worker health in the scheduler, mailbox metadata in the application ledger. Normal scheduler read/write cycles now preserve strictly validated supported metadata. Base jobs/runs/queue and scheduling/lease/retry logic remain unchanged. V2 storage has revisions, provenance, expiry/checkpoint metadata and bounded operation history. No arbitrary extension preservation or competing tracker/database.

Typed local publishers perform pre-validation, locked revision checks, idempotent replay, sequence/session checks, checkpoint/backoff safety and atomic replacement. A shared owned-file helper bounds IO, rejects unsafe paths, verifies source/temp integrity and distinguishes uncertain post-commit outcomes. Reads never migrate/clean/retry; explicit recovery only discards recognized dead-process temps under the owner lock. Generic application-ledger persistence is hardened while its status transitions, submission/approval gates and duplicate checks remain unchanged.

Canonical readers accept v1/v2 metadata and expose conservative quality/state distinctions. Existing dashboard cards display the new recorded health without action buttons or new mutation routes. There are no producer loops, live probes, Graph calls, cursor backend or worker execution enabled. Receipt-artifact verification/publication remains separate work.
