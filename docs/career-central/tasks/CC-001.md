# CC-001 — Canonical read-only career projection (M1)

Status: complete locally, awaiting user review; no commit/release. Requirements: CC-R02, R03, R05, R06, R08.

Deliver a versioned deterministic pure projection and bounded read-only file adapter/CLI reusable by future APIs. Reuse tracker/URL/status parsers. Sources: discovery snapshot, tracker/status history, application JSON ledger, policy, redacted email observations, schedule summaries and profile metadata. Keep source identity/revisions, original states/scores, conflicts and incomplete coverage visible. Recommendations are not applications; uncertain dispatch/HTTP 428 never becomes confirmed submission.

No canonical database, record edits, cloud/web features, new dependency, mailbox/credential access, browser launch, external fetch or submit endpoints. Read only fixed approved source paths and explicit existing path overrides. Never dereference document links, receipt paths or OAuth caches. Output is a private read view, not candidate qualification truth or execution authorization.

Acceptance: fictional fixtures cover tracking vs meaningful URL parameters, distinct/same-title requisitions, collisions, source state conflicts, receipt uncertainty, status corrections, optional-missing vs malformed inputs, redaction, deterministic ordering, source revisions/freshness, path overrides/symlinks, inconsistent multi-file reads, empty counts and absence of writes/network/browser/process side effects. Relevant existing parser/ledger tests must pass without touching personal sources. Record exact results and preservation evidence.

Interfaces: pure function over parsed sources plus synchronous read-only adapter and JSON-to-stdout CLI; no dashboard route. Schemas and module contract must document ownership, provenance and limitations. Finish by updating STATUS, ROADMAP and HANDOFF with evidence and proposed next task; do not start it.
