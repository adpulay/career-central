## Storage contracts

Credential mode defaults to MSAL's process-memory cache. Persistent mode is explicitly selected with `CAREER_OPS_OUTLOOK_CREDENTIAL_MODE=protected`; it uses Microsoft's Authentication Extensions with current-user DPAPI on Windows and Secret Service/LibSecret on Linux, with `usePlaintextFileOnLinux: false`, PII logging disabled, and errors collapsed to fixed codes. A new private configuration carries a random opaque account ID for the protected-store label. Existing config without it must be deliberately migrated before protected mode.

Protected cursor schema `urn:career-central:protected-graph-cursor:v1` is stored through the same OS credential service under separate service and opaque account/scope/checkpoint labels. It has explicit version/revision, owner identities, cursor digest and revoked tombstone. Writes require exact expected revision and use a cooperating owner lock; current-value replay is idempotent. Account/scope/checkpoint change partitions storage. Revocation preserves a tombstone. Only a trusted `withCursor` callback receives raw cursor bytes; metadata inspection returns presence/revision only. The module is not imported by dashboard/API reads. The cursor vault is independent from M3B's dashboard-facing ledger.

M3C mock lifecycle tests invoke `recordWorkerHeartbeat` and `recordMailboxHealth` themselves using fictional events. This validates producer-to-writer behavior without enabling any production polling loop or Graph client.

Do not bridge WSL token storage through Windows PowerShell/DPAPI without a separate security design.
